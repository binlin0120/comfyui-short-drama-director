# 导演全流程

## 1. 输入故事 → 先确认风格

接到原文后，不要直接生成。先提炼：

- 题材、主线、冲突、反转、结局
- 人物清单与关系、情绪弧线
- 可拍成画面的动作/对话，剔除大段心理与纯环境铺陈

然后必须向用户确认画风，例如：

> 这部短剧用哪种画风：写实电影风、二次元少年少女、3D 二次元半写实 CG，还是其他参考图？

## 2. 剧本改编

输出按“场景 + 时间 + 人物 + 动作 + 台词”组织：

```text
【场景】客厅｜夜晚
人物：女主
动作：推门进屋，肩膀垮下，坐到沙发，眼神躲闪，低头落泪
台词：（低声）我怎么也没想到，会是她。
```

规则：心理描写转台词或肢体；单镜头控制台词量；每集结尾留钩子；标注情绪供配音参考。

## 3. 分镜脚本

每行一个镜头，字段至少包含：

```text
镜头号 | 景别 | 画面描述（AI 提示词） | 时长 | 人物动作 | 台词/情绪 | 备注
```

- 单镜头 3-8 秒；冲突用近景/特写，环境用全景。
- 默认 16:9，提示词写明“16:9 cinematic”。
- 每个镜头是一句话+可执行动作+光线+镜头运动，不堆砌大段小说原文。
- 景别、运镜、光线、负面包查 `references/prompt-library.md`，不要每次临场自创。
- 分镜必须落成机器可校验的分镜 JSON（`shots` 数组 + 顶层元数据），
  分镜表 Markdown 作为人工审阅稿保留。

## 4. 角色设定与定妆照

用 JSON 固定每个角色：

```json
{
  "id": "lin_yu",
  "name": "林羽",
  "age": 24,
  "personality": "疲惫、隐忍、被逼到绝境仍冷静",
  "appearance": "20多岁中国青年，黑色微乱短发，白衬衫，深灰西装，眼神疲惫但清醒",
  "style_block": "3D 次世代 CG，国漫半写实，电影级柔光，细腻皮肤材质",
  "voice": {
    "speaker": "Aiden",
    "seed": 202,
    "instruct": "青年疲惫男声，语速偏慢，低沉克制的口语感"
  },
  "seed": 10101
}
```

硬性规则：`appearance + style_block` 是角色的提示词身份证，后续图生图和视频提示词必须原样复用；不同角色之间只替换描述，不重写已认可角色的脸。
- 角色设定必须落成机器可校验的 JSON（`images` 数组或角色名映射），
  每个角色固化定妆照路径、提示词、seed 与音色来源。

## 4.5 模型与参考图锁定

- 项目写明 `model_profile.id`（见 `references/model-profiles.md`），默认是
  `wan2.2-local`；批量中途不换模型。
- 每张参考图/定妆照标 `ref_state`：`REF` 可量产，`PLAN/TODO` 未锁，
  `TTV` 表示镜头直接文生视频不依赖参考图（见 `references/project-files.md`）。
- 量产前执行 `validate_project.py --strict-ref`，强制要求 `REF`/`TTV` 与尾帧信息。

## 5. 镜头提示词结构

每个画面提示词按 `references/prompt-library.md` 的词库组装：

```text
<角色定妆块,接最终定妆照> + <场景/时间/天气> + <动作/表情> + <镜头语言> + <风格块> + , no text, no watermark
```

反向提示词统一包含：`文字，字幕，水印，模糊，变形，多余手指，画得不好的手/脸/眼，画质差`。

## 6. 文字类画面

- 短信、通知、LOGO、倒计时：能后期叠加的优先后期叠字；必须 AI 生成时，把文字写在提示词里并接受逐帧 OCR 质检。
- 角色口播字幕、旁白字幕：一律后期烧录，不交给视频模型生成。
- 用户反馈“字幕精简”“语速太快”后，要同步调整文本与时间轴，不能只把字变小。

## 7. 交付节奏

- 先给分镜和角色设定，用户审。
- 定妆照先出，用户确认后再跑镜头完整版。
- preview（1-2 镜）先出，用户明确说“继续/量产”后才批量铺开。
- 批量前生成批次单与配音对齐单（见 `references/batch-continuity.md`）。
- 完整版包含画面、配音、字幕、音效；每集交付时附质检说明。
- 批量生成前按 `references/validation.md` 跑 `scripts/validate_project.py`，
  FAIL 项全部修复后再进 ComfyUI 管线。
- 清理只在用户批准后执行，且保留“最终版”资产。
